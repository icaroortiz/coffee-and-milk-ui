# Security policy

## Report a vulnerability privately

Use [GitHub's private vulnerability reporting](https://github.com/icaroortiz/coffee-and-milk-ui/security/advisories/new) for a vulnerability in this repository. Include the affected file or version, a minimal reproduction, the impact, and any suggested fix. Use dummy data and redact credentials.

Please do not publish an exploit, access token, customer record, or other sensitive evidence in a public issue. If the private reporting form is unavailable, open an issue requesting a private reporting channel **without disclosing the vulnerability**.

Ordinary layout, documentation, and accessibility bugs can use the public bug-report template. Security issues in upstream packages should also be reported to their respective maintainers.

## Scope and updates

Coffee & Milk UI contains agent instructions, an optional CSS preset, and local UI demonstrations. The examples have no authentication, payment service, or persistent backend. Their mock forms are not production security controls.

Fixes are maintained on the default branch and included in subsequent releases. There is no separate long-term-support branch or guaranteed response time. Use the lockfile, review dependency updates, and apply your application's own server validation, authorization, and data-handling requirements when adapting an example.

## Em português

Para vulnerabilidades, use o [relato privado do GitHub](https://github.com/icaroortiz/coffee-and-milk-ui/security/advisories/new), com passos de reprodução e dados fictícios. Não inclua credenciais ou dados de clientes em issues públicas. Se o formulário privado estiver indisponível, peça um canal privado em uma issue, sem revelar os detalhes do problema. Os exemplos demonstram interface local e não substituem os controles de segurança de uma aplicação real.
